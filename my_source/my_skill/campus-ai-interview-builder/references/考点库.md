# 面试考点库

四岗位的**面试高频追问点**。与笔试题库（`campus-written-test-generator/references/考点库.md`）的差异：

| | 笔试题库 | 本面试库 |
|---|---|---|
| 考察目标 | 会不会（书面作答） | **说不说得清为什么**（口头表达 + 权衡） |
| 典型问法 | "请说明 XX 的原理" | "你当时为什么选它，不选另一个？" |
| 评分焦点 | 答案正确性 | **决策依据、边界意识、踩坑经验** |

每个考点给出三列：**追问点**（面试官会问什么）、**考察什么**（想分辨什么）、**高分信号**（什么样的回答算过关）。

## 一、AI 应用开发岗

### 1.1 技术基础类追问点

| 追问点 | 考察什么 | 高分信号 |
|---|---|---|
| RAG 为什么需要 Rerank？把 K 拉大代替重排行不行？ | 是否理解召回与精排的分工 | 能指出"召回数量增加会引入噪声，且超出上下文窗口后反而稀释关键信息" |
| 向量检索中 HNSW 和 IVF-PQ 怎么选？ | 是否有选型判断框架 | 能给出"精度要求→内存预算→延迟目标"的优先级排序，而非只背特点 |
| 分块策略怎么定？chunk 越大越好吗？ | 对检索质量的理解 | 能说明"块太大导致语义稀释、太小导致上下文割裂"，并给出重叠窗口的作用 |
| 你说用了 XX 模型，为什么不用 YY？ | 是否有真实选型过程 | 能说出具体约束（成本、延迟、中文能力、上下文长度），而非"大家都用它" |
| 幻觉问题怎么解的？ | 是否有系统性方案 | 能分层说明：检索侧（提高召回质量）、生成侧（引用约束）、产品侧（拒答机制） |

### 1.2 工程实现类追问点

| 追问点 | 考察什么 | 高分信号 |
|---|---|---|
| 你的检索延迟是多少？瓶颈在哪？ | 是否有真实测量 | 能区分 Embedding 耗时、向量检索耗时、LLM 生成耗时三段，并指出哪段占大头 |
| 如果并发量翻 10 倍会怎样？ | 是否想过扩展性 | 能识别瓶颈（向量库连接、LLM 限流、内存），给出至少两个具体措施 |
| 怎么评测效果好坏？ | 是否有评估意识 | 能区分检索侧指标（Recall@K）与应用侧指标（人工评分），并说明为何两者都要看 |
| token 成本怎么控的？ | 是否有成本意识 | 能说出上下文裁剪、模型分级路由、缓存等具体手段及各自代价 |

### 1.3 项目类追问点

| 追问点 | 考察什么 |
|---|---|
| 这套方案是你自己设计的还是参照别人的？ | 真实参与度 |
| 开发中最卡的一个问题是什么？怎么解决的？ | 排障能力与真实性 |
| 如果重做一遍，你会改哪里？ | 复盘与成长性 |
| 这套方案的局限是什么？ | 边界意识（答"没有局限"是减分项） |

## 二、Agent 开发岗

### 2.1 技术基础类追问点

| 追问点 | 考察什么 | 高分信号 |
|---|---|---|
| ReAct 循环什么时候停？怎么防止死循环？ | 是否踩过实际坑 | 能给出最大步数限制、重复动作检测、成本熔断等具体机制 |
| Function Calling 的参数解析失败怎么办？ | 容错设计意识 | 能说出重试、schema 收紧、降级为纯文本提示等分层处理 |
| 短期记忆和长期记忆怎么分工？ | 记忆架构理解 | 能说明上下文窗口的限制，以及摘要/向量记忆的取舍 |
| 多 Agent 协作比单 Agent 强在哪？开销在哪？ | 是否盲目追新 | 能客观指出多 Agent 的通信开销、状态一致性成本，并说明何时不值得 |
| 为什么要用 MCP？和直接调 API 差别在哪？ | 对协议价值的理解 | 能说出标准化接入、工具复用、解耦等价值，也能指出引入的复杂度 |

### 2.2 工程实现类追问点

| 追问点 | 考察什么 | 高分信号 |
|---|---|---|
| 任务在中途失败了怎么恢复？ | 状态管理意识 | 能说出检查点（checkpoint）设计、状态持久化位置 |
| 工具返回结果特别长怎么办？ | 上下文管理 | 能说出截断策略、摘要压缩、关键字段提取及各自信息损失 |
| 怎么调试一个行为异常的 Agent？ | 可观测性 | 能说出需要记录轨迹（每步思考/工具调用/返回）、逐步骤定位 |
| 怎么衡量 Agent 好不好用？ | 评估意识 | 能给出任务成功率、平均步数、成本/任务三个维度 |
| Agent 越权操作怎么防？ | 安全意识 | 能说出权限最小化、危险操作需人工确认（human-in-the-loop） |

### 2.3 项目类追问点

| 追问点 | 考察什么 |
|---|---|
| 你的 Agent 有几个工具？怎么决定用哪个？ | 设计思路清晰度 |
| 有没有出现工具选错的情况？怎么改善的？ | 真实踩坑经验 |
| 怎么保证多轮对话不跑偏？ | 上下文控制能力 |
| 你觉得这个 Agent 最不适合处理什么任务？ | 边界意识 |

## 三、技术支持岗（含售前 / 售后）

### 3.1 通用追问点

| 追问点 | 考察什么 | 高分信号 |
|---|---|---|
| 客户报"系统很慢"，你的第一步是什么？ | 是否有结构化方法 | 能先问清范围（哪些用户、什么时段、哪个功能），而非直接猜原因 |
| 你怎么判断是产品问题还是客户环境问题？ | 归责判断能力 | 能说出对比验证（标准环境能否复现）、缩小范围的方法 |
| 客户情绪激动时怎么沟通？ | 沟通与预期管理 | 能先说"我理解这个问题影响很大"，再给明确的时间节点承诺 |
| 一个问题反复出现三次，你会做什么？ | 是否有沉淀意识 | 能提出沉淀为 FAQ、推动产品侧修复、加监控告警 |

### 3.2 技术支持 / TSE 方向

| 追问点 | 考察什么 | 高分信号 |
|---|---|---|
| 排查一个线上问题，你的分层顺序是什么？ | 方法论 | 能按网络→应用→数据分层，且说明为何这样排序 |
| 日志太多怎么快速定位？ | 检索能力 | 能说出按时间窗+关键字段过滤、用 trace id 串联 |
| 接口报 4xx 和 5xx，排查方向有何不同？ | 归责意识 | 能区分客户端问题与服务端问题，及各自的验证方式 |
| 复现不了的问题怎么办？ | 应对不确定性 | 能说出加日志/埋点、扩大样本、与用户约定观察期 |

### 3.3 售前方向

| 追问点 | 考察什么 | 高分信号 |
|---|---|---|
| 客户提了一个产品做不到的需求，你怎么回应？ | 承诺边界意识 | 不直接拒绝，而是重新定义问题、提出替代方案，且不越界承诺 |
| 客户问"你们和竞品比有什么优势"，你怎么答？ | 客观表达能力 | 能按客观维度（功能/性能/成本/生态）对比，不贬低竞品 |
| 怎么判断一个需求是真实需求还是随口一提？ | 需求甄别能力 | 能说出追问使用场景、频次、当前解决方式 |
| POC 做到什么程度算成功？ | 目标界定能力 | 能在开始前与客户对成功标准达成共识 |

### 3.4 售后方向

| 追问点 | 考察什么 | 高分信号 |
|---|---|---|
| 上线后发现严重 bug，你怎么办？ | 应急处置能力 | 能说出立即回滚、同步客户、评估影响面、事后 RCA |
| 客户环境升级失败，回退方案怎么定？ | 风险预案意识 | 能说出升级前备份、灰度验证、明确回退触发条件 |
| 客户要续约了但使用率很低，你怎么做？ | 客户成功思维 | 能分析使用率低的原因，提出价值兑现的具体动作 |
| 客户数据能导出给你排查吗？ | 数据安全意识 | 能指出需要脱敏、权限审批、日志留存的合规边界 |

## 四、产品岗

### 4.1 通用追问点

| 追问点 | 考察什么 | 高分信号 |
|---|---|---|
| 你怎么排需求优先级？ | 是否有方法论 | 能给出具体框架（RICE/Kano）并说明为何选它，而非"重要紧急四象限"这类空话 |
| "提升用户体验"具体指什么？ | 概念落地能力 | 能拆解为可度量的指标 |
| 你怎么知道这个改动有效？ | 实验设计意识 | 能说出对照组、样本量、观察周期、归因难点 |
| 如果数据不支持你的判断怎么办？ | 客观性 | 能承认并说明如何修正，而非硬撑 |

### 4.2 AI 产品类追问点（重点）

| 追问点 | 考察什么 | 高分信号 |
|---|---|---|
| AI 产品答错了怎么办？ | 失败态设计 | 能区分"拒答"与"答错"的严重性，设计兜底与转人工路径 |
| 用户对 AI 的期望过高怎么管理？ | 预期管理 | 能在交互上明确能力边界、给出置信度或来源提示 |
| AI 功能的指标怎么定？ | 指标设计 | 能区分采纳率、修改率、任务完成率，并说明各指标反映什么 |
| 大模型能力升级后，产品逻辑要改吗？ | 演进思维 | 能指出哪些设计是为弥补模型短板、模型变强后可移除 |

### 4.3 项目类追问点

| 追问点 | 考察什么 |
|---|---|
| 这个需求是你自己想的还是别人给的？ | 需求来源真实性 |
| 你怎么验证这个需求值得做？ | 判断依据 |
| 项目上线后有什么反馈？ | 闭环意识 |
| 如果资源只有一半，你会砍掉什么？ | 取舍能力 |

## 五、命题时的考点分配建议

每岗 4 题建议按此层级组合，保证梯度：

| 题目 | 层级 | 目的 |
|---|---|---|
| 第 1 题 · 技术基础 | 原理 + 对比/边界 | 筛掉只会背定义者 |
| 第 2 题 · 项目深挖 | 真实经历 + 决策依据 | **分辨真做过还是看过文档** |
| 第 3 题 · 场景分析 | 系统设计 + 权衡 | 拉开高分段 |
| 第 4 题 · 实操手撕 | 动手能力 + 边界意识 | 验证工程落地能力 |

### 跨岗位重复检查

生成后列出全部 16 题的考点关键词，按下表核对：

| 检查项 | 处理 |
|---|---|
| 同一关键词出现在 2 个岗位 | 若考察角度相同 → 替换其中一题 |
| 同一岗位内 2 题考察同一方向 | → 替换，需覆盖不同层级 |
| 项目类题在 4 岗重复用同一模块 | → 各岗应从不同角度切入同一项目（如 AI 岗看检索实现，产品岗看需求决策） |

> 同一项目在四个岗位出题是**合理且推荐**的——因为面试中四个岗位的面试官看的是同一个项目的不同侧面。关键是角度必须不同。
