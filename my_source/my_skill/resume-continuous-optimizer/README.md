# resume-continuous-optimizer

校招简历持续优化工作流 Skill——多版本简历结构化拆解、代码事实核实、校园简历优化器五项审核与同步更新。

## 功能特性

- **项目经历结构化拆解**：按「项目简介 / 背景 / 核心工作 / 产出」四层级重构，背景采用因果递进段落式表述
- **代码事实核实**：通过本地仓库或 GitHub 仓库核实简历中的所有数字（测试数、异常类数、接口数等），无法核实的改为定性描述
- **五项审核标准**：过度包装检查、AI 味检查、数据可信度检查、应届生身份匹配、面试深挖测试
- **多版本同步更新**：核心事实一致，侧重点因目标岗位而异
- **修改可追溯**：所有修改标注具体内容和原因，定时任务只做审核不自动修改

## 适用场景

- 简历内容定期审核与优化
- 新增项目经历后的结构化拆解
- 代码事实核实（通过 GitHub 仓库验证简历数据）
- 多版本简历的同步更新
- 投递前的交叉审核

## 使用方法

### 方式一：作为 AI Agent 的 Skill 加载

1. 将本目录放置到 Skill 搜索路径中
2. 在对话中触发简历优化相关需求时，AI Agent 会自动加载本 Skill
3. 按 Skill 中的工作流程执行

### 方式二：作为提示词直接使用

1. 打开 `SKILL.md`
2. 复制全文作为系统提示词或用户提示词
3. 配合你的简历内容和具体需求使用

### 方式三：作为定时任务的工作流参考

1. 参考 `SKILL.md` 中的「定时任务建议」章节
2. 配置定时触发（如每周一次）
3. 定时任务只生成审核报告，不自动修改文档
4. 所有修改经用户确认后执行

## 核心原则

1. **真实性第一**：所有描述必须朴素、可信，严禁凭空编造数据
2. **禁止过度包装**：严禁使用「主导」「牵头」「显著提升」「行业领先」等词汇
3. **拒绝 AI 味**：避免使用「赋能」「抓手」「闭环」「矩阵」等空洞词汇
4. **背景段落要求**：必须是因果递进的一段话，禁止分点
5. **产出要求**：体现项目特色，有具体结果，不能泛泛
6. **修改可追溯**：所有修改标注具体内容和原因

## 输出格式

### 审核报告

按五项标准逐条检查，包含：
- 发现问题（具体位置 + 原表述）
- 修改建议（建议表述 + 修改原因）
- 已核实准确的数据项
- 有偏差或无法核实的数据项
- 待用户确认事项

### 修改记录

每次修改必须记录：
- 修改位置（哪个版本 + 哪个部分）
- 修改前（原表述）
- 修改后（新表述）
- 修改原因（为什么修改，依据是什么）
