# 经历梳理

把用户口述的零散经历加工成简历可直接使用的表述。核心价值：从"描述过程"升级为"动作 + 内容 + 结果"，用量化数据支撑，并标注体现的能力。

## 与其他简历类 Skill 的分工

- **本 Skill**：从零提炼素材——用户口述零散经历，加工成简历可用表述；用户说"写简历/改简历"但给出的是经历片段时，也由本 Skill 处理
- **campus-resume-optimizer**：改写已有简历——用户给出完整简历文本，要求去过度包装、按 STAR 重构
- **resume-continuous-optimizer**：持续维护——多版本简历定期审核、代码事实核实、同步更新

## 流程

### 第 1 步：盘点经历

把用户给出的经历按类型分组：实习 / 项目 / 比赛 / 校园经历 / 社团经历 / 学生工作。信息太笼统（只有一句"我做过 XX"）时，先问清楚时间、角色、职责，再进入加工；信息足够则直接加工，不必反问。

### 第 2 步：逐段加工

对每段经历做三件事：

1. **提炼做了什么**：抓住"我做了哪个动作、改变了什么"，不复述流水账。把"参与了 XX 活动的筹备"改写成"负责 XX 活动的 XX 环节，实现 XX"。每条 bullet 都要有产出物或影响，不能停在"协助""接触""了解"。
2. **量化**：为每条表述匹配量化维度。各经历类型的常用维度：
   - 实习：业务规模、效率提升、产出数量、覆盖人数/范围、金额
   - 项目：用户量/性能指标、完成周期、技术难度、成果（上线/获奖）
   - 比赛：参赛队伍数（做分母衬托名次）、名次、获奖比例、个人贡献
   - 社团/学生工作：管理人数、活动场次、参与人数、覆盖率、满意度、预算金额
3. **组装成"动作 + 内容 + 结果"**：动词开头（负责/策划/搭建/优化/推动/主导/撰写），中间是具体做的事，结尾是结果或影响。「主导」仅限真实主导过的校园活动/社团工作；实习与项目经历慎用——应届生场景下"主导项目"最容易被面试官深挖质疑。

### 第 3 步：缺口标注（诚实原则，最重要）

**绝不编造数据。** 用户没提供的数字，在表述中用「XX」占位，并集中列出"待补充数据"清单，方便用户逐项回忆填写。宁可留空也不虚构——简历上每个数字面试都会被追问。

### 第 4 步：能力标签

每段经历标注体现了哪些能力（沟通表达、运营、数据分析、项目管理、执行力、领导力、抗压、学习力等），并附一句依据，说明这段经历为什么能证明该能力——这也是用户面试自我介绍的素材。

## 输出格式

每段经历按此结构输出：

> **经历类型 · 组织/公司名 · 角色**
> - 简历表述（可直接粘贴）：
>   - 负责XX，通过XX方式，实现XX结果（XX数据）
> - 待补充数据：①… ②… ③…
> - 体现能力：XX、XX（一句依据）

多段经历全部处理完后，末尾给整体建议：哪段最值得放简历靠前位置、哪些表述还有数据可挖。用户提到目标岗位（产品/运营/技术等）时，按该岗位视角取舍表述和排序，突出岗位关心的关键词。

## 示例

用户输入：

> 我在学生会宣传部做过部员，主要就是给活动写推文、做海报，还运营过公众号。

输出：

> **校园经历 · 学生会宣传部 · 部员**
> - 简历表述：
>   - 撰写活动宣传推文 XX 篇、设计海报 XX 张，支撑 XX 场校园活动的宣传落地
>   - 参与运营学生会公众号，任职期间粉丝增长 XX / 单篇最高阅读量 XX
> - 待补充数据：①推文篇数与海报数量 ②覆盖的活动场次 ③公众号粉丝增长或阅读量
> - 体现能力：内容写作、执行力；若补齐阅读量/涨粉数据，还能体现运营能力

## 注意

- 含金量高的经历写 2–4 条 bullet，一般经历 1–2 条即可，不要平均用力。
- 一次给多段经历时，全部按同一格式处理，最后统一汇总待补充数据清单，不要每段问一轮。
- 主动追问时一次最多问 3–5 个最关键的缺口，优先问最能提升含金量的数据。
- 「简历表述」的 bullet 保持纯净：只允许「XX」占位，不写"选你实际负责的部分""如XX"这类提示语——可选项和填写说明统一放到「待补充数据」里。
- 用户给出补充数据后，把对应「XX」占位替换为真实数字并重新输出该段表述。
