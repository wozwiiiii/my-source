# 考点库

四类岗位的校招高频考点清单。命题时按岗位取出对应表格，为每道题选取**不同层级**的考点（原理层 / 工程层 / 业务层），避免三题重复考察同一方向。

> 说明：本清单覆盖国内一二线中大厂校招的通用考点范围，不针对特定公司的具体考题。难度定位为校招统招标准——即要求候选人具备扎实基础与一定工程理解，但不要求生产级经验。

---

## 一、AI 应用开发岗

### 原理层
| 考点 | 考察角度 |
|---|---|
| RAG 检索链路 | 分块策略（固定长度 / 语义 / 递归）、召回与重排的分工、召回不足 vs 幻觉的关系 |
| 向量索引选型 | 精确检索 vs HNSW vs IVF-PQ，召回率与内存/延迟的取舍 |
| 相似度度量 | 余弦相似度 / 内积 / 欧氏距离的适用差异，为何归一化后内积等价于余弦 |
| Prompt 工程 | few-shot 与 CoT 的适用边界、结构化输出（JSON mode / function calling）的可靠性 |
| 幻觉抑制 | 引用溯源、检索必需化、拒答机制的常见做法与副作用 |
| 推理优化 | KV Cache 的作用与显存代价、批处理（continuous batching）、量化（INT8/INT4）的精度损失 |
| 上下文窗口 | 长文本截断策略、滑动窗口、摘要压缩的信息损失 |

### 工程层
| 考点 | 考察角度 |
|---|---|
| 文本分块实现 | 分隔符递归切分、重叠窗口设计、元数据保留 |
| 检索结果融合 | RRF（倒数排序融合）的实现、多路召回结果合并去重 |
| 异步与并发调用 | 批量请求的并发控制、限流与重试、超时处理 |
| 缓存设计 | 语义缓存 vs 精确缓存、缓存命中率与一致性问题 |
| 成本控制 | token 计数、上下文裁剪、模型分级路由 |

### 业务层
| 考点 | 考察角度 |
|---|---|
| 效果评估 | 检索侧（Recall@K、MRR）与应用侧（人工评分、A/B）的差异 |
| 冷启动 | 无标注数据时如何构建评估集 |
| 场景适配 | 客服问答 vs 文档分析 vs 代码助手的链路差异 |

## 二、Agent 开发岗

### 原理层
| 考点 | 考察角度 |
|---|---|
| ReAct 循环 | 思考-行动-观察的迭代机制、何时终止、与纯 prompt 的本质差异 |
| 工具调用协议 | Function Calling 的 schema 定义、并行调用、参数校验失败的兜底 |
| 记忆管理 | 短期（会话窗口）vs 长期（外部存储）、摘要记忆与向量记忆的取舍 |
| 任务规划 | Plan-and-Execute 与 ReAct 的差异、静态规划 vs 动态调整 |
| 自我反思 | Reflexion 机制的作用与"反思循环不收敛"的风险 |
| 多 Agent 协作 | 角色分工、消息传递、冲突消解的开销 |
| MCP 协议 | 协议定位（工具/资源的标准化接入）、与直接 API 调用的差异 |

### 工程层
| 考点 | 考察角度 |
|---|---|
| 循环控制 | 最大步数限制、死循环检测、成本熔断 |
| 工具容错 | 参数解析失败重试、工具超时、部分失败降级 |
| 状态持久化 | 中断恢复、检查点（checkpoint）设计 |
| 上下文压缩 | 工具返回结果过长时的截断与摘要 |
| 可观测性 | 轨迹（trace）记录、每步耗时与 token 统计 |

### 业务层
| 考点 | 考察角度 |
|---|---|
| 可靠性设计 | 幻觉工具调用、越权操作的防护 |
| 人机协作 | 何时交由人工确认（human-in-the-loop） |
| 效果评估 | 任务成功率、步数效率、成本/任务 |

## 三、技术支持岗（含售前 / 售后工程师）

> **岗位细分说明**：技术支持类是一个岗位族，校招常见细分包括 **技术支持工程师（TSE）**、**售前工程师（Pre-sales / 解决方案工程师）**、**售后工程师（Post-sales / 客户成功工程师）**。三者共享"懂技术 + 懂客户"的底座能力，但考点重心差异明显：
>
> | 细分方向 | 核心职责 | 考点重心 |
> |---|---|---|
> | 技术支持 / TSE | 答疑、复现、排障、工单处理 | 排查方法论、日志与 SQL、复现能力 |
> | 售前工程师 | 需求理解、方案讲解、竞品对比、POC | 方案设计、技术宣讲、招投标与合规问答 |
> | 售后工程师 | 部署交付、SLA 履约、问题闭环、客户关系 | 交付流程、变更管理、客户沟通与续约 |
>
> 命题时若用户指定了具体细分，按对应重心出题；未指定则默认以技术支持/TSE 为主，第 3 题适度覆盖售前或售后场景。

### 3.1 通用底座（三类细分均需掌握）

| 考点 | 考察角度 |
|---|---|
| 客户沟通 | 技术语言与业务语言的转换、非技术人员的解释能力 |
| 问题闭环 | 从受理到验证解决的全流程、避免"答了但没解决" |
| 文档能力 | 排查记录、方案说明、FAQ 的可读性与准确度 |

### 3.2 原理层

**技术支持 / TSE**

| 考点 | 考察角度 |
|---|---|
| 排查方法论 | 分层定位（网络→应用→数据）、二分法缩小范围、假设-验证循环 |
| 日志体系 | 日志级别设计、结构化日志、关联 ID（trace id）的作用 |
| 链路追踪 | 分布式调用链的组成、如何定位延迟瓶颈 |
| HTTP 状态码 | 4xx 与 5xx 的归责差异、常见码的排查方向 |
| SLA / SLO | 可用性计算（几个 9）、错误预算、与业务的关系 |

**售前工程师**

| 考点 | 考察角度 |
|---|---|
| 需求挖掘 | 显性需求 vs 隐性需求、从客户描述中提炼真实痛点 |
| 方案匹配 | 客户需求与产品能力的映射、**能力边界**的诚实说明 |
| 竞品对比 | 客观维度对比（功能/性能/成本/生态）而非主观贬低 |
| POC 设计 | 验证目标的界定、成功标准的共识、避免"演示即交付"误解 |
| 技术宣讲 | 分层表达（对技术听众 vs 对决策者）、演示环境的可控性 |

**售后工程师**

| 考点 | 考察角度 |
|---|---|
| 交付流程 | 部署、验收、培训的标准环节、交付物清单 |
| 变更管理 | 生产环境变更的审批与回滚、窗口期选择 |
| 版本与兼容 | 版本升级路径、依赖兼容性核查、补丁策略 |
| 数据安全 | 客户数据的脱敏、日志留存的边界、权限最小化 |

### 3.3 工程层（实操）

**技术支持 / TSE**

| 考点 | 考察角度 |
|---|---|
| SQL 排查 | 慢查询定位（EXPLAIN）、索引失效场景、锁等待 |
| 接口复现 | 用 curl / Postman 构造最小复现、参数比对 |
| 日志检索 | 按时间窗 + 关键字段过滤、从异常栈回溯 |
| 配置核查 | 环境变量、连接池、超时参数的常见错配 |
| 依赖排查 | DNS、证书过期、上游服务状态确认 |

**售前工程师**

| 考点 | 考察角度 |
|---|---|
| 方案文档撰写 | 现状分析→方案设计→实施计划→收益预估的完整结构 |
| 环境验证 | 搭建演示/测试环境、构造贴近客户真实数据的样例 |
| 招投标应答 | 技术条款逐条响应、偏离项的说明方式 |
| 收益测算 | TCO / ROI 的估算逻辑、口径必须与客户对齐 |

**售后工程师**

| 考点 | 考察角度 |
|---|---|
| 故障复现 | 在客户环境中安全复现、最小化对生产的影响 |
| 环境比对 | 客户环境与标准环境的差异清单、逐项排查 |
| 回滚演练 | 回滚方案的可行性验证、数据一致性保障 |
| 升级操作 | 灰度升级、健康检查、升级失败的回退路径 |

### 3.4 业务层

**技术支持 / TSE**

| 考点 | 考察角度 |
|---|---|
| 工单流转 | 分级（P0-P3）、升级路径、响应时效约定 |
| 用户沟通 | 安抚话术与信息同步节奏、预期管理 |
| 根因分析 | RCA 报告要素、如何区分直接原因与根本原因 |
| 知识沉淀 | 常见问题库（FAQ）与自动化自助的边界 |

**售前工程师**

| 考点 | 考察角度 |
|---|---|
| 客户预期管理 | 承诺能力的边界、避免过度承诺导致交付风险 |
| 多方博弈 | 技术决策者 / 使用者 / 采购方的诉求差异与协调 |
| 失单复盘 | 丢标原因分析、可改进项与不可控因素的区分 |
| 商机判断 | 需求真实性、预算与周期的可行性初判 |

**售后工程师**

| 考点 | 考察角度 |
|---|---|
| SLA 履约 | 响应时效与解决时效的达成、违约的沟通处理 |
| 客户续约 | 使用深度、价值感知、续约风险的早期识别 |
| 事故沟通 | 重大故障时的信息同步节奏、责任边界与善后 |
| 需求反馈闭环 | 把客户诉求转化为产品需求、反馈进展的机制 |

## 四、产品岗

### 原理层
| 考点 | 考察角度 |
|---|---|
| 需求优先级 | Kano 模型、RICE 评分、MoSCoW 的适用差异 |
| 实验设计 | A/B 实验的样本量与显著性、常见的实验污染 |
| 指标口径 | DAU / MAU / 留存 / 转化率的定义陷阱（口径不一致导致的误判） |
| 用户研究 | 定性访谈与定量问卷的适用边界 |
| MVP | 最小可行产品的界定标准与常见误用 |

### 工程层（实操）
| 考点 | 考察角度 |
|---|---|
| 埋点设计 | 事件/属性定义、埋点方案表、漏埋与重复上报 |
| 需求拆解 | 从一句话需求到用户故事、验收标准（AC）的写法 |
| PRD 要素 | 背景/目标/范围/流程/异常分支/数据需求的完备性 |
| 竞品分析 | 分析维度的选取、避免主观褒贬的客观表述 |

### 业务层
| 考点 | 考察角度 |
|---|---|
| 优先级冲突 | 业务方诉求 vs 技术成本的协调 |
| 效果归因 | 多因素变动下的归因困难、对照组设计 |
| 增长权衡 | 商业化与用户体验的平衡、短期指标与长期价值 |
| AI 产品设计 | 不确定性输出的产品化处理（失败态、兜底、用户预期） |

## 五、考点选取建议

命题时每个岗位的 3 道题建议按此组合选取，以确保梯度：

| 题目 | 推荐层级 | 目的 |
|---|---|---|
| 第 1 题 | 原理层（含对比/边界） | 筛出基本功不扎实者 |
| 第 2 题 | 工程层（含边界/异常/性能） | 区分"会背"与"会做" |
| 第 3 题 | 业务层（含权衡） | 拉开高分段 |

> 注意：同一岗位的 3 道题**不要都落在同一技术方向上**。例如 AI 应用岗若第 1 题考 RAG 检索，第 2 题宜转向工程侧的并发/缓存/成本，而非继续考分块策略。
